# 发布文案

## 发布前固定交付

这是作品制作的固定收尾阶段。用户要求准备发布时，连续完成并一次性交付全部内容：四平台标题、简介、标签、章节时间表、合集建议及3:4和4:3两张完整封面。不要逐项等待用户索要，也不把封面提示词当作成图交付。缺最终音视频等真实依据时说明具体缺口，完成其余可独立工作。封面固定风格与尺寸读取 references/cover-style-v1.md 和 configs/publishing.json；只生成这两种比例，旧版其他比例保留但不纳入新发布包。

将本期完整发布包保存为 PROJECT/publishing/package_v01.json，包含 titles（四平台标题对象）、description（简介）、tags（非空字符串列表）、collection（action/name/description/reason）、chapters_file（相对项目路径）、covers（以3:4、4:3为键的相对项目图片路径）。collection.action为existing、create或suggest_create；已有合集未知时用suggest_create，说明只是建议。修改另存版本。

使用已配置Python运行 scripts/publishing.py PACKAGE.json --package --output 发布包.md，一次校验所有必需项、标题章名长度、章节时间与最终音频/文稿版本、两张图片实际像素并生成可复制的完整发布文案。校验不代替中文与构图目视检查。交付Markdown和两张封面链接，标明合集是否仅为建议；不自动上传、创建合集或发布。

用户要求“准备发布”“发布文案”时，主动提供：四平台适配标题及字数、简介、推荐标签、章节时间表。不能漏掉章节划分；单独修改标题时只需更新标题，不强制重复其他已有内容。

同时提供合集归属建议：优先使用合适的已有合集；没有合适合集时建议新建并给出名称、简介。未知已有合集列表时，不把建议名称当作已存在的合集，不自动创建或发布。

所有平台的发布章节名统一不超过12字，优先使用简短、清晰的章名。章序、标点、空格等若包含在名称中均计数，时间戳单独展示，不计入章名。精简只影响发布章名，不改完整口播标题、字幕或章节时间。用 scripts/publishing.py --chapters 章节JSON绝对路径校验后交付。

章节表提供可直接复制的“MM:SS 章节名”，超过1小时使用HH:MM:SS。包括00:00开场、正文每章和结语。可另给精简的发布章名，同时保存文稿完整标题作为对应依据，不能为简洁改变章节主题。

以最终音频的章节标题起读时间或剪辑后的实际章节切点为准。优先核对最终转录的逐词时间、章节合并与补录记录；不要把含上一章结尾的长段cue起点当成下一章起点。标记时间取整到秒时向下取整，保留JSON中的小数秒供追溯。时间严格递增且小于片长，章节必须与定稿结构一致。

保存 PROJECT/publishing/chapters_v01.json 和 chapters_v01.md，包含最终音频哈希、文稿哈希、真实片长、时间来源，以及各章start、timestamp、title、full_title。修改或补录后另存新版本，不覆盖旧版。若发布视频加了片头、删减或变速，必须按最终视频重新核对时间，不直接复用配音时间。缺最终时间依据时明确列出缺口，不编造时间。交付章节表不等于已经在平台添加章节，也不自动发布。

用户要求标题、发布文案或修改标题时，每次均提供小红书、抖音、视频号、快手四个适配版本。标题可以共享核心问题，但应按各平台长度重新组织，不能省略任一平台，也不能机械截断词语或书名。简介、推荐标签按用户请求提供，不把标签拼入标题后漏算字数。

读取 configs/publishing.json：小红书不超过20字，抖音不超过30字，视频号不超过16字，快手无字数上限。这是用户指定的工作约束。每个汉字、标点、数字、字母、空格均计1个字符；避免emoji与组合字符造成计数歧义。输出时标注字数，超限先重写再交付。标题应准确体现内容，不编造效果或承诺改变命运。

将本期选定标题另存为 PROJECT/publishing/titles_v01.json，后续修改另存新版本，格式：

```json
{
  "xiaohongshu": "小红书标题",
  "douyin": "抖音标题",
  "weixin_channels": "视频号标题",
  "kuaishou": "快手标题"
}
```

交付前使用已配置Python运行本技能 scripts/publishing.py 标题JSON绝对路径。脚本只校验四平台完整性、非空单行文本和字数，不代替Agent判断标题质量，不自动发布、不上传作品。
